# 第二组 Overhead：第877个配置保存异常修复

第877个配置已完整提交到 checkpoint；失败位置是 `run_manifest.json.tmp` 替换正式清单时的 Windows `WinError 5`。只读审计确认当前 v2 配置1–877全部完整，共7016条方法/模式结果、847个可进入固定任务成对统计的 seed。磁盘另有473个旧v1 checkpoint，不能混入本次结果。

## 错误及修复

原代码对 Windows 文件访问/共享拒绝没有重试，并采用固定临时文件名。同目录多个写入进程还可能共用这个名字。异常后 `finally` 又开始物化数GB轨迹，造成长时间没有明显进展，以及不同导出批次的 raw 文件。现有堆栈不能确定具体哪个进程占用了清单文件。

- 所有第二组 JSON/gzip、CSV、PDF/PNG 和报告采用同目录唯一临时文件，关闭句柄、同步后再原子替换。
- Windows访问/共享错误按50/100/200/400/800ms间隔重试。持续失败保留完整恢复文件，异常中给出路径；不会先删除目标或原地覆盖。
- 正常运行与单独绘图使用同一个结果目录锁，阻止两个新入口同时写入。
- checkpoint先提交；进度日志/清单失败只报警。清单每30个配置更新，恢复以checkpoint为准。
- 异常及Ctrl+C清理只保存状态，不启动大量事件导出。正常仿真结束后才逐checkpoint导出，显示阶段和进度。
- 汇总文件全部提交后才允许绘图。旧运行清单处于running/interrupted等状态时也拒绝单独重绘，避免使用中断期间混合导出的文件。
- 读取checkpoint的访问错误直接报告；八条均为程序执行异常的配置允许重试。真实协议超时和未完成记录仍保留并按原统计规则处理。
